## Compatibility gate

PocketVault 2.5.0 accepts only the current authenticated V2 vault format. It deliberately rejects V1 and early V2 data that omit required KDF, vault-ID, associated-data, integrity, manifest-binding, digest, or size metadata.

- [ ] With the official 2.4.0 build, unlock a synthetic legacy vault, let 2.4.0 migrate it, and export a fresh `.hpb` backup.
- [ ] Import that fresh backup into the 2.5.0 candidate and verify passwords, notes, categories, TOTP entries, and attachments.
- [ ] Confirm a deliberately unsupported legacy vault or backup is rejected without replacing or mutating the original data.
- [ ] Keep the 2.4.0 installation and original test backup until the new backup has been verified.

Never use production credentials or a real user vault for these checks.

## Publication and traceability

- [ ] Replace `Unreleased` in `CHANGELOG.md` with the actual release date.
- [ ] Commit the final candidate and create signed tag `v2.5.0` from that exact commit.
- [ ] Build the signed `googlePlayRelease` AAB from the tag and record its SHA-256 digest.
- [ ] Upload that exact AAB to Play Console and retain the release record.
- [ ] Download the Play-generated signed Universal APK from the same bundle record.
- [ ] Verify package, version, Play App Signing certificate, offline manifest, and APK SHA-256 with `scripts/publish-github-release.sh`.
- [ ] Publish the GitHub Release from `v2.5.0`, attaching only the Play-generated Universal APK.
- [ ] Record the tag, commit, version mapping, AAB hash, APK hash, and Play App Signing certificate fingerprint in the final release notes.

Do not publish a locally generated APK signed with the upload key, a debug key, or any certificate other than the official Play App Signing certificate.
