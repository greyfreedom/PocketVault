## Compatibility and data-safety gate

- [ ] Install the Play-signed candidate over an official 2.5.1 installation containing a current schema 1 vault.
- [ ] Unlock without modifying the vault, then create or edit one entry and confirm an automatic encrypted backup is created before schema 3 is activated.
- [ ] Restore the pre-upgrade backup and verify passwords, secure notes, categories, TOTP entries, attachments, thumbnails, biometrics, and password hints.
- [ ] Repeat the first-write upgrade with a synthetic schema 2 vault containing ordered custom fields, and verify the fields survive schema 3 activation.
- [ ] Force an automatic-backup or staged-commit failure and confirm the original vault remains byte-for-byte unchanged.
- [ ] Create and edit each supported payment-card brand; verify cardholder name, number, expiration, security code, notes, categories, attachments, and custom fields after relock and restart.
- [ ] Confirm card numbers, security codes, concealed custom-field values, passwords, and TOTP secrets stay masked by default and never appear in search results.
- [ ] Confirm plain-text custom-field names and values are searchable as designed, while concealed values remain excluded.
- [ ] Confirm early V2 authenticated migration still succeeds with the master password and that V1 vaults and backups remain rejected without mutation.

Use synthetic credentials and disposable test data only. Never test a release candidate against the sole copy of a real vault.

## Publication and traceability

- [ ] Replace `Unreleased` in `CHANGELOG.md` with the actual publication date.
- [ ] Commit the final candidate, then run `./scripts/tag-release.sh` to create, verify, and push signed tag `v2.6.0` from that exact commit.
- [ ] Build and upload the signed `googlePlayRelease` AAB, then record its SHA-256 digest.
- [ ] Download the Play-generated signed Universal APK from the same bundle record.
- [ ] Verify version, package, Play App Signing certificate, offline manifest, and hashes with `scripts/publish-github-release.sh`.
- [ ] Publish the GitHub Release from `v2.6.0`, attaching only the Play-generated Universal APK.

Do not publish a locally generated APK signed with the upload key, debug key, or any certificate other than the official Play App Signing certificate.
