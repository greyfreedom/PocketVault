## Compatibility and data-safety gate

- [ ] Install the Play-signed candidate over an official 2.5.0 installation containing a synthetic early V2 vault wrapped with 100,000 PBKDF2 iterations.
- [ ] Unlock with the master password and verify passwords, notes, categories, TOTP entries, attachments, thumbnails, and password hint.
- [ ] Confirm an automatic `pocketvault_backup_*.hpb` is created before the upgraded directory is activated.
- [ ] Confirm the upgraded config uses a fresh 16-byte salt, 600,000 iterations, a non-empty new vault ID, associated-data version 1, and complete integrity metadata.
- [ ] Restore the automatic legacy V2 backup with 2.5.1 and verify that import normalizes it before activation.
- [ ] Force insufficient storage or a staged-write failure and confirm the original vault remains byte-for-byte unchanged with a dedicated upgrade error.
- [ ] Confirm biometric unlock requests the master password for an early V2 vault and works again after the user explicitly re-enables it.
- [ ] Confirm V1 local vaults and V1 backups remain rejected without replacement or mutation.

Use synthetic credentials and disposable test data only. Never test a release candidate against a sole copy of a real vault.
